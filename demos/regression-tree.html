Grow a regression tree

Click to add points. Drag the depth slider and watch the tree carve the data into boxes, one split at a time.

For a startup working on greener concrete, I built an optimisation engine that suggests concrete recipes. A key design choice was to model how a recipe behaves with regression trees rather than a black box. A tree is just a sequence of yes/no questions, so people could see why a recipe was suggested.

How a tree is grown

A regression tree splits the input space into boxes \(R_1, \dots, R_J\) and predicts a constant in each, the average of the training points that land there:

$$\hat f(x) = \sum_{j=1}^{J} c_j\,\mathbf 1[x \in R_j], \qquad c_j = \frac{1}{|R_j|}\sum_{x_i \in R_j} y_i.$$

Finding the best boxes overall is intractable, so trees are grown greedily. At each node, try every feature \(j\) and every threshold \(s\), split into \(R_L = \{x_j \le s\}\) and \(R_R = \{x_j \gt s\}\), and keep the split that reduces the squared error the most:

$$\min_{j,\,s}\Big[\sum_{x_i\in R_L}(y_i - \bar y_L)^2 + \sum_{x_i\in R_R}(y_i - \bar y_R)^2\Big].$$

Repeat on each side until a stopping rule kicks in: a maximum depth, a minimum number of points per leaf, or no split that helps enough.

Try: drag the dashed line. Notice: each side predicts its own average, and the total squared error changes with the threshold. The tree picks the threshold at the bottom of the error curve.

Depth

A tree of depth \(D\) has at most \(2^D\) leaves. Shallow trees are easy to read but miss structure (high bias). Deep trees can fit almost anything, including noise (high variance). In practice you pick the depth with cross-validation, or you prune a deep tree back by penalising the number of leaves \(|T|\):

$$C_\alpha(T) = \sum_{j=1}^{|T|}\sum_{x_i\in R_j}(y_i - c_j)^2 + \alpha\,|T|.$$

Try it yourself

Click anywhere to add a point. Increase the depth and the tree gets more questions, fits better, and eventually starts chasing noise.

Try: click to add points, then drag the depth. Notice: each extra level adds more questions. At depth 1–2 the tree misses the shape; at depth 6–7 it starts chasing single noisy points.

Why trees

  • Interpretability. A shallow tree can be read out loud: "if the cement content is above this and the replacement share is below that, expect this strength". That builds trust with engineers who know concrete far better than any model.
  • No assumptions about shape. Trees handle thresholds and interactions naturally, which suits material properties that change abruptly.
  • Easy to plug into an optimiser. A tree is cheap to evaluate, so a genetic algorithm can call it thousands of times. See Evolve a greener recipe for that half of the story.

The same greedy splitting is the building block of random forests (many trees on bootstrapped data) and gradient boosting (trees fitted one after another to the remaining errors).
